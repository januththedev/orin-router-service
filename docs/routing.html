Routing

There are no manual routes to configure. For each request the router builds a candidate list from your enabled providers — exact model matches first, wildcards after, in the order you added them — and tries them top-down. First success wins.

Failover semantics

  • 429 / 5xx / timeout / unreachable — that provider cools down, request moves on.
  • 401 / 403 — credentials are dead: the whole provider is skipped for the rest of the request.
  • 400 / 404 — model-level problem: next provider immediately, no cooldown.
  • Streaming — same rules before the first byte; once streaming, failures arrive as an in-band error (sent content can't be recalled).

Health is observed, never guessed

Cooldowns and latency tracking come from real outcomes only. The dashboard's provider health, median latencies and error rates are computed from your actual request logs — no synthetic probes, no fake status.
