Orin Router / Introduction

Canonical cloud inference

Orin Router is the single Vercel-compatible inference boundary used by Orin Core and future Orin clients. Human identity, quota reservation, and canonical usage remain in Core. Router records provider-attempt facts and never charges the user twice.

Request path

  1. Core reserves one usage unit and mints a short-lived service assertion.
  2. Router verifies the assertion and Core revocation state.
  3. Router resolves the exact public alias against fresh zero-price catalog snapshots.
  4. Up to three eligible providers are attempted before stream commit.
  5. Provider attempt facts are written transactionally for Core reconciliation.

Security boundaries

  • Only four exact aliases are public.
  • Raw provider IDs and user-supplied base URLs are rejected.
  • Production rate and health state require shared Redis.
  • Missing shared state fails closed.
  • Secrets never appear in responses or logs.
